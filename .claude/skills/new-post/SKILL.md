# New Post — сквозной прогон одного поста

Команда для главного агента (оркестратора): выполнить шаги 1-3 из
`content-pipeline/SKILL.md`, но для ОДНОГО поста и полностью
самостоятельно — без вопросов пользователю на промежуточных шагах.
Единственная точка, где нужно спросить — превью в конце (Шаг 5 ниже).
Не путать с `content-pipeline` — та команда проверяет расписание/очередь
целиком и может звать `new-post` как раз для пополнения; `new-post` сама
по себе занимается только одним конкретным постом.

## Шаг 1 — тема и дата

1. Определи следующую свободную дату очереди: посмотри даты в именах
   файлов `posts/*.json`, возьми следующий будний день после самой
   поздней занятой даты.
2. Если пользователь передал источник/тему аргументом ($ARGUMENTS) —
   используй её. Если нет — не спрашивай пользователя: поручи
   `content-researcher` самому выбрать следующую по приоритету
   неиспользованную тему из `context/sources.md` (агент сам может
   прочитать `posts/*.json` через Glob/Read, чтобы не повторить уже
   использованные темы/источники — явно укажи ему это сделать).

## Шаг 2 — ресёрч и картинка

1. Запусти `content-researcher` с темой/источником и датой из Шага 1.
2. Как только черновик готов — запусти `image-generator` на этом файле.

## Шаг 3 — ревью и автоматическое исправление (без вопросов пользователю)

1. Запусти `governance-reviewer` на файле (текст + картинка).
2. Дальше действуй по вердикту, не спрашивая пользователя, пока сама
   можешь закрыть проблему:
   - **ГОТОВ К ПУБЛИКАЦИИ** → обнови `status` на `reviewed`, иди к Шагу 4.
   - **НУЖНЫ ПРАВКИ** — конкретные стилевые правки с готовым «было/стало»
     примени сама (Edit), не пересоздавая пост. Если ревьюер отметил
     факт, который не смог проверить сам (нет веб-доступа) — проверь его
     сама через WebFetch по `source.url` (или другому релевантному URL) и
     либо подтверди как есть, либо исправь/убери неподтверждённое.
   - **БЛОКИРУЮЩАЯ ПРОБЛЕМА** — если причина в отсутствии веб-доступа у
     ревьюера, а не в найденной ошибке — сама проверь факт через WebFetch
     и, если подтвердился, считай проблему закрытой. Если факт
     действительно не подтверждается или тема не соответствует
     источнику — поручи `content-researcher` переписать нужный фрагмент
     или сменить тему целиком (как при замене источника — см. прецедент
     в `context/sources.md`), затем возвращайся к этому шагу заново.
   - Если картинка забракована (артефакты) — поправь `image_prompt`
     (убери противоречия, сузь композицию, если проблема была в сложной
     детали вроде рук крупным планом) и запусти `image-generator` заново.
3. После любой правки — запусти `governance-reviewer` повторно на
   изменённом файле. Максимум 3 круга правок подряд. Если после третьего
   круга вердикт всё ещё не «ГОТОВ» — останови автоматический цикл и
   опиши пользователю, что именно не удаётся закрыть самостоятельно
   (это тот редкий случай, где вопрос пользователю оправдан — контент
   реально проблемный, а не формальность).

## Шаг 4 — превью (единственная обязательная остановка)

Собери HTML-превью поста в эмуляции Telegram (та же разбивка
подпись+продолжение, что использует `telegram-publish/SKILL.md`) и
покажи пользователю. Дождись явного «да» — без этого `status` не
меняется на `approved`, никакие дальнейшие действия не выполняются
автоматически.

Если пользователь просит правки на этом шаге — вернись к Шагу 2/3 с его
конкретными замечаниями, затем повтори Шаг 4 заново.

## Шаг 5 — после согласования

Как только пользователь одобрил превью — обнови `status` на `approved`.

**Fast-track.** Если у поста `"priority": "fast-track"` И
`governance-reviewer` вынес «FAST-TRACK: ПОДТВЕРЖДЁН» — после смены
статуса выполни вставку в начало очереди по под-шагу «Шаг 3.6» из
`content-pipeline/SKILL.md` (ближайший свободный слот, сдвиг дат
остальных одобренных постов на +1 будний день, ре-синк на сервер). Не
дублируй механику здесь. Иначе — пост просто остаётся на своей дате.

Больше ничего делать не нужно: пост уже стоит в очереди,
публикация произойдёт по стоящему правилу автопубликации из `CLAUDE.md`
без дополнительных действий с чьей-либо стороны. Сообщи пользователю
итог одной строкой: тема, дата очереди, статус (и пометь, если пост
пошёл по fast-track).
