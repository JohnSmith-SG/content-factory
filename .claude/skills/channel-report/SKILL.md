# Отчёт по Telegram-каналу

Канал: **@ai_pro_cg**. Отчёт охватывает три периода: последние сутки, 7 дней, 30 дней (сегодня включительно).

**Что этот отчёт покрывает:** рост аудитории, трафик сайт↔канал, **число комментариев** за периоды (сам разбор комментариев — по-прежнему `content-pipeline` Шаг 0, не здесь).

**Что НЕ покрывает:** реакции (эмодзи) и клики «English version» — считать их без телефонной сессии Telegram нечем, а deep-link-клики в `bot_listener.log` не агрегированы. Если понадобится — добавить отдельно.

**Чего нет вообще без телефонной сессии Telegram:** источники подписчиков (поиск/ссылка/репост), график прироста, доля отключивших уведомления. Для этого нужен `stats.getBroadcastStats` по пользовательской сессии (не по токену бота) — не разворачивали.

## Откуда данные

| Блок | Источник |
|---|---|
| Подписчики: сейчас + история по дням | `metrics_report.py` на VPS (живой `getChatMemberCount` + файл `logs/metrics.jsonl`, куда `bot_listener.py` пишет снимок раз в сутки) |
| Комментарии за периоды | `metrics_report.py` считает строки `logs/comments_for_review.jsonl` (total и отдельно «от подписчиков», без анонимных админ-комментов владельца) |
| Переходы сайт → канал (`click_channel`) | Янд.Метрика, счётчик 111567095, цель `click_channel` — точно |
| Переходы канал → сайт | Яндекс.Метрика, визиты с источником Telegram — приблизительно (реферер из ТГ-браузера часто теряется) |

Токен Метрики и id целей переиспользуются из `Career/.claude/secrets/` (те же, что у `/site-report`, доступ только на чтение статистики).

## Шаг 1. Забрать данные по подписчикам с сервера

Один вызов:

```
bash .claude/scripts/vps.sh ssh 'python3 /opt/content-factory/metrics_report.py'
```

Вернёт `LIVE_SUBSCRIBERS: <N>` и блок `=== SNAPSHOTS ===` — строки `{"date","ts","subscribers"}` по дням.

- **Сейчас** = `LIVE_SUBSCRIBERS`.
- **Было сутки/7д/30д назад** = снимок с датой, ближайшей к (сегодня − 1 / − 7 / − 30). Если снимков за нужный день нет (сервис только запущен, выходные пропущены) — бери самый ранний из имеющихся и в отчёте пометь «с DD.MM» вместо точного периода.
- **Прирост** = сейчас − было. Если истории меньше 2 дней — так и напиши: «первый замер, динамика появится завтра».

Тот же вывод содержит блок `=== COMMENTS ===` — JSON `{"total": {...}, "from_subscribers": {...}}`, ключи `1d / 7d / 30d / all`. В отчёте бери `total` за период и в скобках `from_subscribers` (комментарии владельца как анонимного админа в `from_subscribers` не входят).

## Шаг 2. Забрать данные из Яндекс.Метрики

Один вызов PowerShell (все запросы внутри скрипта, чтобы не плодить окна подтверждения — тот же приём, что в `/site-report`):

```powershell
& "C:\Users\kitrina.lashonne\Documents\KitrinaClaudeCode\Zerocoder\content-factory\.claude\skills\channel-report\collect-channel-metrika.ps1"
```

Метки в выводе:
- `CLICK_CHANNEL:day|7d|30d` — массив `[визиты, достижения_цели, конверсия%]`. Достижения цели = число переходов на канал с сайта.
- `SOCIAL:7d|30d` — массив `{"n":соцсеть,"v":визиты}`. Ищи строку `Telegram` (или `telegram`) — это переходы из ТГ на сайт, классифицированные как соцсеть.
- `SOURCES:30d` — массив `{"n":тип источника,"v":визиты}` (Прямые заходы, Переходы по ссылкам, Из социальных сетей, Мессенджеры, Внутренние переходы …). Показывает, в какой «ящик» вообще попадает трафик из ТГ; если `SOCIAL` пуст, ориентир — строка «Мессенджеры» / «Из социальных сетей».

Если `Telegram` нет ни в `SOCIAL`, ни заметной строки «Мессенджеры» в `SOURCES` — значит переходов из канала на сайт за период Метрика не зафиксировала (либо их нет, либо все ушли в «прямые заходы»). В отчёте пиши `0 (либо учтены как прямые заходы)`.

## Шаг 3. Собрать отчёт и сразу сохранить (до вывода в чат)

Если в `content-factory/reports/` уже есть прошлый отчёт — открой его, возьми прошлые числа для строки «Было» / раздела «Вывод». Затем **удали** старый файл (в папке держим только один, самый свежий) и запиши новый как `content-factory/reports/YYYY-MM-DD-channel-report.md` инструментом Write — **до** вывода чего-либо в чат (иначе карточка тул-колла Write вклинится в текст).

**Единый стиль таблиц (обязательно):** все три таблицы — одна форма, ровно 4 колонки `|  | Сутки | 7 дней | 30 дней |`, заголовок первой колонки пустой, две строки данных. Никаких «назад» в заголовках. Столбцы в исходнике выровнены пробелами по ширине. «Сейчас» для подписчиков — отдельной строкой **над** таблицей, не колонкой.

```markdown
# Отчёт по каналу @ai_pro_cg — {дата}

**Канал:** https://t.me/ai_pro_cg · снимки подписчиков с {дата первого снимка}
**Метрика сайта:** Яндекс.Метрика 111567095 (цель click_channel, источник Telegram)

## Подписчики

Сейчас — **{N}**.

|         | Сутки | 7 дней | 30 дней |
|---------|-------|--------|---------|
| Было    | {N}   | {N}    | {N}     |
| Прирост | {±N}  | {±N}   | {±N}    |

## Комментарии

|                | Сутки | 7 дней | 30 дней |
|----------------|-------|--------|---------|
| Всего          | {t}   | {t}    | {t}     |
| От подписчиков  | {s}   | {s}    | {s}     |

## Трафик сайт ↔ канал

|              | Сутки | 7 дней | 30 дней |
|--------------|-------|--------|---------|
| Сайт → канал  | {r}   | {r}    | {r}     |
| Канал → сайт  | {v}   | {v}    | {v}     |

Сайт → канал — цель `click_channel` (точно). Канал → сайт — визиты из Telegram (приблизительно). {1 строка про общий трафик сайта, если уместно.}

## Вывод

{2–3 предложения: растёт ли аудитория и с какой скоростью; появились ли комментарии от подписчиков; заметен ли эффект от конкретных событий (рассылка друзьям, публикация); что показывает трафик между сайтом и каналом; сравнение с прошлым отчётом, если он был}
```

Числа — строго из ответов, ничего не додумывать. Нет данных за период — ставь `0` или `—`, строку не пропускай. Если истории снимков < 2 дней — строка «Было» = `—`, «Прирост» = `—`, плюс пометка «первый замер» абзацем под таблицей.

## Шаг 4. Показать в чате одним сообщением

Одним сообщением: блоки «Подписчики», «Комментарии», «Трафик сайт ↔ канал» (без раздела «Вывод» — он только в файле; допустима 1–2 строки контекста после таблиц), и сразу следом строкой: `Отчёт сохранён в content-factory/reports/YYYY-MM-DD-channel-report.md`.
