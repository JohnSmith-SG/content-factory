# Telegram Publish

Публикует один пост в Telegram-канал **@ai_pro_cg** через бота **@ai_pro_cg_bot**
(Telegram Bot API — без сторонних сервисов вроде Postiz).

## Перед публикацией

Всегда показывай пользователю текст поста и путь к картинке и жди явного
подтверждения — публикация необратима (пост сразу увидят подписчики канала).

## Токен

Токен бота лежит в `.claude/secrets/telegram_bot.token` (в корне этого проекта).
Никогда не выводи его содержимое в чат. Подставляй в команды через файл,
не печатай значение в текст ответа.

## Как публиковать

Telegram жёстко ограничивает подпись к фото (`caption`) 1024 символами —
это лимит платформы, обойти нельзя. Наши посты — 1500–1800 символов,
поэтому весь текст в подпись не влезает. Формат, который договорились
использовать (вместо двух незаметно связанных сообщений «фото» + «текст»):

**Фото с короткой подписью (заголовок + первый абзац) → следом полный
остаток текста одним сообщением, с явной пометкой-переходом.**

1. Взять поле `platforms.telegram.content` из JSON-файла поста.
2. Разбить текст на абзацы по `\n\n`. Абзац 0 — заголовок, абзац 1 — первый
   содержательный абзац (обычно ключевой факт/контекст).
3. **Подпись к фото (caption):** `<b>{заголовок}</b>\n\n{абзац 1}\n\n👇 Продолжение`.
   Стрелка уже означает «дальше/ниже» — не добавляй к ней слово «ниже»,
   это дублирует смысл. Проверь, что итог ≤ 1024 символов (обычно
   заголовок+1 абзац укладываются с большим запасом — заголовок ~50-100
   символов, абзац ~150-350).
4. **Следующее сообщение (sendMessage):** начни с символа `⠀`
   (Braille Pattern Blank — визуально пустой, но не пробел) и `\n\n` —
   иначе текст прилипает к шапке чата. **Обычная пустая строка (`\n`) не
   сработает** — Telegram обрезает её сам, отступа не будет (проверено:
   API вернёт `message is not modified`). Дальше все остальные абзацы
   (со 2-го и до конца, включая вывод), склеенные через `\n\n`, без
   повторения заголовка и первого абзаца. Тоже `parse_mode="HTML"`.
5. Найти соответствующую картинку в `images/` (по дате в имени файла).
6. Chat ID канала — `@ai_pro_cg` (публичный канал, можно использовать
   username вместо числового ID).

Текст в самом JSON-файле не трогай — разбивка на подпись/продолжение и
HTML-разметка добавляются только на этапе отправки, не в источнике.

**Важно про `curl -F` и символ `@`:** curl интерпретирует значение поля,
начинающееся с `@` или `<`, как «прочитать из файла» — это ломает
`chat_id="@ai_pro_cg"` (curl попытается открыть файл с именем `ai_pro_cg`).
Правило:
- Для `chat_id`, `parse_mode` и любых обычных текстовых значений —
  используй `--form-string "имя=значение"` (буквальная строка, без
  спецобработки `@`/`<`).
- Для самого файла картинки — `-F "photo=@путь/к/файлу.jpg"` (тут `@`
  обязателен, это и есть загрузка файла).
- Для длинного текста — не передавай текст напрямую в аргументе (риск
  проблем с кавычками и переносами строк), а сначала запиши его в
  temp-файл (например, `tmp/<дата>-publish-text.txt`, кодировка UTF-8,
  **без CRLF** — на Windows `python3 -c "...open(..., newline='')..."`,
  не обычный `echo`), затем передай `-F "text=<tmp/<файл>.txt"` (тут `<`
  обязателен — это чтение содержимого файла в значение поля, а не
  file-upload).

Пример вызова (ключ подставляется из файла, никогда не печатается):

```bash
BOT_TOKEN=$(cat .claude/secrets/telegram_bot.token | tr -d '\r\n ')
curl -sS -X POST "https://api.telegram.org/bot$BOT_TOKEN/sendPhoto" \
  --form-string "chat_id=@ai_pro_cg" \
  -F "photo=@images/2026-08-24-rid-ai-governance-study.jpg"
```

Если текст длиннее 1024 символов (почти всегда так), отправляй его
отдельным сообщением сразу следом:

```bash
# заголовок + текст заранее записаны в tmp/<дата>-publish-text.txt
# первая строка обёрнута в <b>...</b>, файл в UTF-8 без CRLF
BOT_TOKEN=$(cat .claude/secrets/telegram_bot.token | tr -d '\r\n ')
curl -sS -X POST "https://api.telegram.org/bot$BOT_TOKEN/sendMessage" \
  --form-string "chat_id=@ai_pro_cg" \
  --form-string "parse_mode=HTML" \
  -F "text=<tmp/2026-08-24-publish-text.txt"
```

Если в тексте встречаются символы `<`, `>` или `&` — экранируй их как
`&lt;`, `&gt;`, `&amp;` перед отправкой (HTML-разметка Telegram требует
этого для остального текста, не только для заголовка).

## После публикации

1. Проверь ответ API — поле `"ok": true` означает успех.
2. Если `"ok": false` — самая частая причина: у бота нет прав администратора
   в канале (`Post Messages`). Сообщи об этом пользователю прямо, не пытайся
   обойти проверку.
3. Сообщи пользователю ссылку на пост: `https://t.me/ai_pro_cg/<message_id>`
   (`message_id` берётся из ответа API, поле `result.message_id`).
4. Удали временные и вспомогательные файлы этого поста из `tmp/` (черновики
   подписи/продолжения, base64 картинки, ответы API, промежуточные версии
   картинки) — ориентир: дата поста в имени файла. Файл поста в `posts/` и
   картинку в `images/` не трогать — см. `CLAUDE.md`, раздел «Уборка после
   публикации».
